## 这是什么

一个「技能互换平台」的产品设计原型。用户发布**「我能教的」**和**「我想学的」**，
平台负责把他们匹配起来并推动互换完成。

**要解决的问题**：很多人想学新技能，但报班贵、自学难坚持；同时自己擅长的技能
又缺少分享和变现渠道。技能互换看起来是双赢解法，但真正做起来卡点很多。

---

## 核心洞察：双重巧合

技能互换要求 **A 能教的 = B 想学的**，**且 B 能教的 = A 想学的** ——
两个条件必须同时成立，这是**双边匹配**，不是单边。

按 100 个技能标签、每人能教/想学各 3 个估算：

| 指标 | 数值 |
|---|---|
| 单向命中概率 | ≈ 8.7% |
| **双向同时命中** | **≈ 0.8%** |

也就是说，**一千次配对里只有约 8 次能真正换起来**。用户来两次没结果就走了，
产品根本转不动。

> **所以第一性问题不是「界面怎么设计」，而是「怎么打破双边锁死」。**
> 页面上所有机制都围绕这一件事展开。

## 设计了什么

### 五项机制

| 机制 | 作用 |
|---|---|
| **① 技能币** | 把「双边易货」降级为「多边交易」—— 我教你赚币，用币去学别人，不再要求双方刚好互补。**这是破解双重巧合的根本手段** |
| **② 三层匹配漏斗** | L1 精准互匹（体验最优）→ L2 技能币匹配（保证有结果）→ L3 技能环三人循环（冷启动兜底） |
| **③ 互试一节课** | 双方各教 30 分钟、免费，双向评价后再决定是否继续 —— 启动成本从「报名一门课」降到「聊半小时」 |
| **④ 双向信用分** | 完成互换加分、鸽人扣分；评价**双向对称**，不只学员评老师，老师也评学员「好不好教」 |
| **⑤ 技能地图** | 把「人列表」换成「技能节点 + 供需状态」，平台可立刻识别哪项技能供不应求 |

### 六阶段履约链路

```
① 破冰 → ② 互试课 ★ → ③ 定计划 → ④ 履约跟踪 → ⑤ 完成结算 → ⑥ 身份转化 ★
```

每一阶段都标注了**流失点与对策**。其中：

- **② 互试课** 是关键取舍点（决定「是否继续」）
- **⑥ 身份转化** 是**增长命门** —— 学会的技能自动加入「我能教」清单，
  把学员变成老师。**如果用户学完就走，平台永远缺老师、永远要靠补贴拉供给。**

### 增长飞轮

```
更多学习者 → 更多互换需求 → 学成者转为老师 → 供给池扩大
    ↑                                              ↓
    └────────── 匹配成功率上升 ←──────────────────┘
```

**前提**：匹配率低于阈值时飞轮根本不会转。**这也是技能币是「启动器」
而不是增长手段的原因 —— 它决定了飞轮能不能被推动第一圈。**

## 可交互的部分

打开原型页后，找到「**04 · 可交互演示**」板块：

1. 左侧是「我的技能名片」（能教：吉他弹唱 / 摄影构图；想学：Python 入门 / 视频剪辑）
2. 点击 **「开始匹配」**
3. 页面会**依次跑三层匹配**：L1 精准互匹 → L2 技能币匹配 → L3 技能环撮合
4. 注意看 L2 出现时，**右上角的技能币会从 3 扣到 1** —— 用一次真实操作演示
   「技能币如何把双边巧合拆成单边匹配」
